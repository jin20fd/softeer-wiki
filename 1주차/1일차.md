## JAVA의 Thread 모델
### `Runnable` 인터페이스

```java
@FunctionalInterface
public interface Runnable {
    public abstract void run();
}
```

### Runnable 인터페이스의 구현체 `Thread`

- 기본 생성자
    
    ```java
    private Thread(ThreadGroup g, Runnable target, String name,
                       long stackSize, AccessControlContext acc,
                       boolean inheritThreadLocals)
    ```
    
    - **g** – 스레드 그룹
    - **target** – run() 메서드가 호출될 객체
    - **name** – 새 스레드의 이름
    - **stackSize** – 새 스레드에 원하는 콜 스택 크기, 0이면 JVM의 기본값을 사용
    - **acc** – AccessControlContext 접근 권한(읽기, 쓰기, 네트워크 설정 등), null이면 AccessController.getContext()를 사용
    - **inheritThreadLocals** – true이면 생성하는 스레드로부터 상속 가능한 thread-local 값들의 초기값을 상속함
        - ThreadLocal :  멀티스레드 환경에서 각 스레드가 독립적으로 사용하는 변수를 저장하기 위한 Java 클래스

Thread를 상속 받아서 사용하거나 Runnable 인터페이스를 구현하여 사용 가능하다

하지만 다른 클래스를 상속받아야 하는 경우, 이중 상속은 불가능해서 Runnable 인터페이스를 구현해야 한다


### 과제에서 주어진 코드에서 사용된 스레드

주어진 코드 : `RequestHandler` 를 target으로 하여 스레드 생성
```java
Thread thread = new Thread(new RequestHandler(connection));
thread.start();
```

사용된 생성자를 직접 확인해보았다.

```java
public Thread(Runnable target) {
      this(null, target, "Thread-" + nextThreadNum(), 0);
}

public Thread(ThreadGroup group, Runnable target, String name,
                  long stackSize) {
        this(group, target, name, stackSize, null, true);
}
```

## JAVA의 Concurrent 패키지
**Concurrent 패키지** : 동시성 작업을 위한 유틸리티 클래스를 제공

스레드를 미리 만들어두고 사용하면 응답속도가 개선될 수도 있지 않을까라는 생각이 들어,  
Concurrent 패키지의 ExecutorService를 활용하여 스레드풀을 활용하도록 변경해보았다.
 
`ExecutorService executorService = Executors.newFixedThreadPool(50);`

Thread만을 생성하는 기존 방식과 어떠한 차이가 있는지 확인하기 위해, 각 스레드에서 `Thread.sleep(200)`를 호출하여 확인해보았다.  
 여러 스레드가 동시에 동작하는걸 확인할 수 있었지만, 
기존 코드에서 개선된 점을 확인할 방법을 찾지 못하였고, 큰 필요성을 깨닫지 못하였다.
