### **Encoding / Decoding**

- **Encoding** : 데이터를 특정 형식으로 변환하는 과정
- **Decoding** : 인코딩된 데이터를 다시 원래대로 복원하는 과정

URL 경로에서 한글은 UTF-8로 인코딩 되어 전달된다.

따라서 java에서 제공하는 유틸 클래스인 `StandardCharsets` 를 활용하여 다음과 같이 UTF-8 방식을 사용하여 한글 문자를 디코딩하여 저장하였다.

```java
String value = URLDecoder.*decode*(keyValue[1].trim(), StandardCharsets.*UTF_8*);
```

### 데이터베이스에 값이 저장이 안되는 문제

동기화가 안 되어서 발생하는 문제인가 했는데, 테스트를 해보니 당연히 아니었다. 

데이터베이스 클래스에서 사용자 정보를 Map으로 저장하고 아이디를 key로 갖는데 같은 아이디로 테스트해서 발생하는 문제였다. 

**데이터베이스 동기화의 필요성**을 발견하여 해결방안을 생각해보아야 겠다. concurrent 패키지를 활용해볼 수 있겠다 → 스쿼드세션에서 `ConcurrentMap`을 활용하여 해결할 수 있다는 것을 알았다.

## 스쿼드 세션

- **RequestHandler의 생성자 인자 관리**
    
    RequestHandler의 생성자에 너무 많은 값을 전달하고 있어서 RequestData, ResponseData를 생성자로 전달하는 것이 아니라 RequestHandler 내부에서 생성하는 것에 대한 피드백을 받았는데, 이 부분을 보완 하려고 한다.
    
- **static {} - Java의 정적 초기화 블록**
    
    코드를 보면서 새로운 문법을 배우게 되었다. 클래스가 처음 로딩될  때에 static 변수의 초기화에 주로 사용한다고 한다.
    
    ```java
    public class MyClass {
      static List<String> list = new ArrayList<>();
    
      static {
        list.add("a");
        list.add("b");
      }
    }
    ```
    
- **builder 패턴**
    
    User 객체의 정보를 저장하도록 구현한 동료분의 코드를 보고, 파라미터 순서에 의존하지 않고 객체를 생성할 수 있다는 점에서 좋다고 생각하여 적용해보려고 한다.
    
- **DB의 동시성 문제**
    
    static 으로 선언되어 있어서 문제가 발생할 수 있는 데이터베이스의 동시성 문제에 대해서 다른 동료분들도 우려를 언급해주셨다. `ConcurrentMap` 으로 해결 가능하다는 것을 알 수 있었다.
    

## 피드백

- **로그**는 파싱 가능하도록 형식을 맞추어 작성할 필요가 있다
    - 기본적으로 구분자가 있어야 한다
    - json 형식을 지원하는 작성하는 것을 추천
- HTTP 규격에 맞도록 **RFC 문서**를 참고하여 개발
    - HTTP 요청의 대소문자 구분
    - Header와 startLine의 공백 처리 (OWS: optional whitespace)
- 반복되는 String은 **상수** 처리
- **String**은 Constant Pool에서 jvm이 관리한다 → String에 대한 학습
- 적절한 **스레드풀** 개수
    - Tomcat의 최대 스레드 풀 개수는 200개
    - 기본 가이드 라인 : CPU bound 기준으로 코어 개수 + 1
        - JAVA에서 코어개수 확인 : `Runtime.getRuntime().availableProcessors();`
- **final** 키워드, effectively final

# 회고
**Keep**

- 오류가 있으면 공유하고 이야기해보기

어제 회고에 작성했던 Try를 실천하였다. 실수에서 비롯한 간단한 오류이긴 했지만, 혼자 고민해보고 디버깅도 해보고, 고민해보다가 팀원들에게 질문하였는데 질문하면서 오류의 원인을 파악하여 해결할 수 있었다. 앞으로도 학습하면서 모르는 것, 구현하다가 발생하는 오류를 적극적으로 공유하여 이야기해보도록 해야겠다.

**Problem**

- 다른 사람의 코드를 빠르게 읽고 이해하는 능력이 부족하다

서로의 코드를 직접 확인하면서 스쿼드 세션을 진행하였는데, 다른 동료분들보다 코드를 읽고 이해하는 속도가 느리다고 느껴졌다. 

**Try**

- 코드 흐름이 보이게 커밋 메시지 작성하기

커밋 메시지를 읽는 사람 입장이 아니라 내가 작업하기 편한 지점에 커밋을 날리고 메시지도 간결하게 작성해왔었다. 당글님이 피드백 시간에 커밋 메시지에 대한 이야기를 해주셨는데, 기존에 커밋 메시지를 작성하던 방식에 대해서 많이 반성하게 되어서 읽는 사람을 고려하여 커밋 메시지를 작성하도록 해야겠다.

- 동료들 코드 구경 많이 하기

내가 작성하지 않은 코드를 빠르게 이해하는 능력이 부족하다고 느껴졌는데, 많이 읽어보면 늘 것 같다고 생각하였다. 그래서 다른 동료들의 PR도 많이 구경해야 겠따.
