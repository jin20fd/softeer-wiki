# ⏳ 회고

### **Keep**

-  구현 과정에서 검증하기 위한 테스트 코드 작성하고 활용하기
    
    HTTP StartLine에 여러 공백이나 잘못된 요청의 경우에 대한 예외처리를 구현하였다.  
    테스트를 위해 사용했던 요청을 보내는 클라이언트(크롬, 포스트맨 등)들은 요청 메시지를 잘 포맷팅해서 전달하기 때문에 잘못된 HTTP 요청을 보내기가 어려웠다.  
    메시지를 파싱하는 MessageParser에 대한 단위테스트를 직접 작성하여 코드를 검증해보았고, 이전까지는 의무적으로 작성해왔던 테스트코드의 필요성을 몸소 깨달았다.
    

### **Problem**

- 파싱 로직 구현에 AI를 활용하여 오히려 더 많은 시간이 소요되었다
    
    AI가 오히려 코드의 전체적인 흐름을 이해하지 못한 코드를 제시해주어서 오히려 코드를 수정하고 작성하는데에 오랜 시간이 소요되었던 것 같다.  
    또한, 지금 만드는 프로그램에서는 메시지를 파싱하는 것이 중요한 요소이기 때문에 되도록이면 스스로 구현해야 겠다.
    

### **Try**

- 프로그램 구조 시각화하기
    
    이제 팀원들과 코드 리뷰를 진행하기 때문에 지금 만들고 있는 웹 서버의 구조를 시각화하면 도움이 될 것 같다는 생각이 들었다.  
    그룹세션, 스퀘드 세션에서도 활용할 수 있을 것 같아서 간단하게라도 웹서버의 구조를 시각화해보아야 겠다.


# 📚 학습 내용

- `application/x-www-form-urlencoded`  : POST 요청의 본문에서 서버로 데이터를 전송하는 데 사용되는 MIME 타입
    - key1=val1&key2=val2 와 같은 형식으로 구성되어 있다
    - [Percent-encoding](https://developer.mozilla.org/en-US/docs/Glossary/Percent-encoding) 되어 바이너리 데이터에는 적합하지 않은 형식이다
