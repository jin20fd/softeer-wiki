## 작업 과정에서의 배운 점

### **WAS 과제**

- **세션 아이디**로 어떤 값을 사용하는 것이 적절할까?
    
    **필요하다고 생각한 조건**
    
    1. 중복되지 않아야 한다
        
        → 서비스 로직에서 중복 여부를 매번 검사하고 싶지 않음
        
    2. 다른 사용자가 예측할 수 없어야 한다
        
        → 세션 탈취 등의 보안 이슈 방지
        
    3. 생성 속도가 빨라야 한다 (추가 조건)
        
        → 요청마다 세션을 생성할 수 있으므로 성능 고려
        
    
    **세션 아이디 후보**
    
    | **방식** | **중복 없음** | **예측 불가** | **생성 속도** | **비고** |
    | --- | --- | --- | --- | --- |
    | **SecureRandom** | 매우 높음 | 매우 높음 | 상대적으로 느림 | 보안 최우선 시 적합 |
    | **UUID (v4)** | 충분히 높음 | 높음 (랜덤 기반) | 빠름 | 실용성과 성능의 균형 |
    | **userId 기반 Random** | 서비스 내부에서 userId의 중복 보장 | 예측 쉬움 | 빠름 | 고유하지만 보안에 취약 |
    
    ⇒ 조건 1(중복 없음), 조건 2(예측 불가) 모두 만족하며 SecureRandom보다 빠르게 생성 가능해 실용적인 `UUID`를 세션 아이디 값으로 활용하기로 결정
    

- **요청 경로에 따라 실행하는 함수를 Map으로 관리하기 위한 함수 추상화**
    - `BiConsumer` 와 `Method`
        - `BiConsumer` : 인자를 두개 받는 함수의 인터페이스
            
            단순히 두 개의 값을 받아 동작을 수행하는 경우에 사용
            
            +) `BiFunction<T, U, R>` : 반환값이 있는 경우
            
        - `Method` : 리플렉션 API의 클래스
            
            런타임에 동적으로 메서드를 선택해서 실행해야 하는 경우에 사용
