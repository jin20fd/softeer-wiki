### 작업 과정에서의 배운 점

- 스프링에서 필터와 인터셉터의 차이
- JVM의 클래스로더로 프로젝트 내의 디렉터리를 확인 가능하다는 것
- 반복문과 스트림의 차이
- TreeMap으로 대소문자
- 501 응답과 404 응답
- 디미터의 법칙

### 어려웠던 점

- 동적 HTML을 구현하기 위한 구조를 만드는 과정이 어려웠다.
    - 로그인 성공 → 메인페이지를 응답한다고 생각해서 이런 오류가 있었다.
        
        POST `/user/login` 요청을 받아서 html을 body에 넣어서 200으로 보내면, base url이 user가 된다.
        
        body로 보내는 html 내에서 css 경로가 상대경로라서 기존 경로로 보내면 오류가 발생한다
        
    - 로그인 성공 → 메인페이지로 리다이렉트 되는 것이니까,
    메인페이지를 그리는 경우에 userManager를 받아서 처리하게끔 하면되는 것이다
    
    **사용자가 메인페이지 요청 /main → userManager에서 사용자 정보 반환 → 그 정보를 바탕으로 html 파일 값 수정 → 응답**
    

# ⏳ 회고

### **Keep**

- 기능에 따라서 클래스 분리하여 구현하기
    
    로그인한 사용자만 접근 가능한 경로들을 관리하는 SessionFilter를 따로 분리하기로 계획하고 바로 구현하였다. 확실히 기능만 개발하고 리팩토링을 진행하는 방식보다 효율적이라고 느껴졌다. 계획 후에 개발하는 것의 중요성을 깨달았다.
    
- 팀원분과 개발 방향에 대해서 이야기 나누어보기
    
    동적 html 기능을 구현하는 방식에 대해서 물어보셔서 이야기를 나누었다. 착각하고 있었던 부분을 팀원분의 이야기로부터 깨달았다.
    

### **Problem**

- 오늘 계획한 할 일을 다 마치지 못하였다.
    
    이번주차 초반에 너무 여유롭게 과제를 진행해서 마지막 과제를 진행할 시간이 부족하였다.
    
    할 일이 많다보니 계획했던 부분들을 자꾸 이정도면 괜찮지 않을까 합리화 하면서 미루게 되었다. 테스트코드를 작성하고 입력에 대한 예외처리를 분리하려고 하였는데, 아직 하지 못하였다. 주말에 시간을 들여서 계획을 실천해야 겠다.
    
- 스쿼드 세션에서 코드에 대한 설명을 잘 하지 못한 것 같다.
    
    개발한 코드들이 많아지다 보니 코드의 모든 부분을 설명하기에는 시간도 부족하고, 전달하는데에도 어려움이 있는 것 같다. 스쿼드 세션 전에 이야기 나누어보고 싶은 부분을 미리 생각해보고 이에 대해서 이야기해보도록 해야겠다.
    

### **Try**

- 코드 구조 시각화하기
    
    이야기 나누고 싶은 부분은 골라서 이야기하려면 코드의 전체적인 흐름을 나타낼 수 있는 구조를 시각화하면 좋을 것 같다.
