### 작업 과정에서의 배운 점

Map으로 사용하던 기존 **데이터베이스를 H2로 옮기기** 위해서 `H2`와 `JDBC`에 대해서 학습하였다.

JDBC API인 `DriverManager`와 `DataSource`에 대해서도 알아보았다.

커넥션 풀 구현체인 `HikariCP`를 사용하고자 하였고, JDBC를 사용하여 데이터베이스와 연결하는 코드를 작성해보았다.

**데이터베이스의 환경변수를 분리**하기 위해서 `System.getenv()`와 `System.getProperty()`의 차이점을 알아보았다. System.getProperty()를 통해 JVM 내부에 시스템 설정을 가져올 수 있다는 것을 알 수 있었다. System.getenv() 를 사용해도 매번 OS의 환경변수에 접근하는 것이 아니라 JVM 메모리 내부에 캐싱한다는 사실을 알 수 있었다.

### 어려웠던 점

- **데이터베이스의 커넥션을 어디서 관리할 것인지**
    
    Static으로 관리하던 데이터베이스를 H2로 옮기고 JDBC를 활용하려고 하였다. WebServerConfig에서 생성해서 주입하는게 맞는지가 고민이다. 데이터베이스가 웹서버에 종속되는 것은 싫어서 WebServerConfig에 넣지 않으려고 고민을 해보았는데, 방법이 떠오르지 않는다. 그래서 우선은 데이터베이스를 관리하는 어떤 클래스를 만들어서 WebServerConfig에 주입하는 방식으로 구현해야 겠다.
    
- **JDBC와 H2에 적용하는 것**
    
    바로 적용할 수 있을 것이라고 생각했는데, 기본 동작(JVM 내부 메모리에서도 동작 가능, 두 개의 프로세스에서 동시에 접근 불가능 등)에 대한 이해가 부족하니 활용하는 것이 어렵다는 것을 느꼈다.

# 📚 학습 내용

- **JDBC(Java Database Connectivity)**
    - Java에서 관계형 데이터베이스 커넥션과 쿼리 실행을 돕는 역할
    - DriverManager와 DataSource
        - DriverManager는 클래스
        - DataSource는 인터페이스, 주로 커넥션 풀 구현체인 HikariCP를 사용한다
- **H2** : JAVA 기반의 관계형 데이터베이스
    - 기본 포트 : 8082
    - JVM 내부 인메모리에서 H2 데이터베이스가 생성 가능하며,  `jdbc:h2:mem:test` 로 접근 가능하다
    - 여러 프로세스에서 동시에 접근이 불가능하다
- **java.sql.Statement의 실행 메서드**
    - **execute()**
        - 모든 쿼리
        - 결과가 ResultSet이면 true
    - **executeQuery()**
        - 읽기 전용, SELECT
        - 반환 타입: ResultSet
    - **executeUpdate()**
        - INSERT, UPDATE, DELETE, DDL
        - 영향 받은 row 수(int) 반환
- **`System.getProperty()` 가 무엇인지, 설정 방법**
    
    실행 시점에서의 정보(user.name, user.dir 등)를 가져올 수 있다
    
    - 명령줄에서 -D 옵션으로 설정
        
        `java -DdbUrl=jdbc:h2:~/test -DdbUser=sa -DdbPassword= -jar app.jar`
        
    - Gradle에서 -P 옵션으로 설정
        
        `./gradlew run -PdbUrl=jdbc:h2:~/test -PdbUser=sa -PdbPassword=`
        
        ```java
        run {
          if (project.hasProperty('dbUrl')) {
            jvmArgs "-DdbUrl=${project.property('dbUrl')}"
            jvmArgs "-DdbUser=${project.property('dbUser')}"
            jvmArgs "-DdbPassword=${project.property('dbPassword')}"
          }
        }
        ```
        
- **`System.getenv()` vs `System.getProperty()`**
    - **`System.getenv()` :** OS 환경 변수를 가져온다
        - OS 환경변수를 native 방식으로 한 번에 읽어오고 캐싱하고, 이후 호출은 Map<String, String>에서 조회하는 방식
        - 이후는 getProperty()와 거의 유사한 속도
    - **`System.getProperty()` :** JVM 시스템 프로퍼티를 가져온다
        - JVM 내부 메모리에서 Properties 객체의 키-값을 찾는 방식
        - O(1) 수준의 해시 탐색으로 매우 빠르다
