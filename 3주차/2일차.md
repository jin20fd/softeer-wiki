# ⏳ 회고

### **Keep**

- 전체 프로젝트의 클래스 다이어그램을 만들어서 설명하기
    
    이번 그룹에서 처음으로 그룹 리뷰를 진행하였는데, 어제 이야기를 나누었던 대로 모두들 자신의 프로젝트의 흐름도나 그래프를 그려서 전체적인 구조를 설명하는 시간을 가졌다. 설명을 하는 입장과 설명을 듣는 입장 모두에서 이해하기 훨씬 편했던 것 같다. 앞으로도 구조가 변경되어도 꾸준히 다이어그램을 업데이트하도록 해야겠다.
    
- 이동 시간 활용해서 가벼운 학습하기
    
    DTO의 유효성을 확인하기 위해서 리플렉션을 활용한 코드를 작성했었는데, 리플렉션에 대한 이해가 부족한 상태로 구현했었다고 생각이 들어서 이동 시간에 리플렉션 관련 영상을 시청하며 학습하였다. 짧은 시간이지만 학습에 대한 부담과 기대가 적어서 학습 효율이 오히려 좋다고 느껴졌다. 앞으로도 이동시간을 활용해서 블로그를 보거나 영상을 보면서 가볍게 학습하면 좋을 것 같다.
    

### **Problem**

- 의도가 명확히 드러나지 않게 질문을 한다.
    
    프로젝트 회의를 진행할 때에 ‘이 기능은 구현이 필요한가요?’ 라고만 질문을 하면 ‘이 기능은 이러한 의도라면 필요하지 않을 수도 있을 것 같아서 드린 질문입니다’ 와 같이 질문의 의도가 명확히 드러나지 않아서 다시 설명을 해야하는 상황이 있었다. 특히 프로젝트 회의를 할 때에는 상대방이 질문의 의도를 명확하게 파악할 수 있도록 질문해야 겠다. 더 나아가서, 의도를 잘 드러나지만 너무 길지 않고, 날카롭지 않게 정리하여 말하는 연습도 필요할 것 같다.
