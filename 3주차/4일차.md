### 작업 과정에서의 배운 점

- multipart/form-data 데이터 형식의 구조
- 명세를 이해해야 구현흐름을 잡을 수 있다는 것
    
    멀티파트폼 형식을 막연히 파싱하려고 하니 너무 막막했다. RFC문서를 확인하면서 형식의 정의에 대해서 알아보고 나서 파일, 텍스트를 분리할지와 헤더의 속성들을 사용할지에 대한 기준을 세울 수 있었다.
    
- 302/301 응답의 차이와 SEO
- try-with-resource

### 어려웠던 점

- 부족한 시간내에 WAS 과제의 기능을 구현하는 것
- 여러 고려사항을 기반으로 배차 알고리즘을 작성하는 것
    
    시간과 위치의 범위가 너무 넓어서 이런 요소들을 배차 알고리즘을 구현할 수 있도록 설정하는 것이 어려웠다.

# 📚 학습 내용

- multipart/form-data
    
    각 파트에 포함 가능한 MIME 헤더 : Content-Disposition, Content-Type
    
    Content-Disposition의 값은 무조건 form-data
    
    filename 파라미터의 값을 무조건 신뢰해서는 안된다
    
    전달하는 데이터가 파일(이미지)인지는 filename 여부로 확인할 수 있다
    
    [RFC 7578: Returning Values from Forms: multipart/form-data](https://datatracker.ietf.org/doc/html/rfc7578#section-4.2)
