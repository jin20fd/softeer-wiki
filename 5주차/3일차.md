- [x]  외부 API 호출을 위한 요청, 응답 형식 분석

### 작업 과정에서의 배운 점

- **QueryDSL**
    
    두가지 조건으로 필터링 해야 하는 쿼리를 작성하기 위해서 QueryDSL을 처음 사용해보았다. if 문으로 분기처리를 해서 다른 쿼리를 요청했었는데, 동적 쿼리를 활용해서 편리하게 구현할 수 있다는 것을 알게 되었다.
    

### 어려웠던 점

- **구현한 기능이 제대로 동작하는지 검증하는 것이 어려웠다**
    
    날짜 범위와 예약 상태를 기준으로 필터링하여 예약 정보를 가져오는 기능을 구현하는데, 날짜 범위가 제대로 필터링되는지 확인하기 어려웠다. 테스트 코드의 필요성을 또 한 번 느끼게 되었다. 오늘은 작성하지 못 했지만 이슈로 생성해서 이번주 중으로 작성해야 겠다.
    
- **여러 종류의 API를 사용 가능하고, 사용하는 외부 API가 변경되어도 적용 가능하도록 추상화하는 것**
    
    여러 API를 호출하고, 또 사용하는 API가 변경될 수도 있기 때문에 이 두 가지를 모두 고려하여 구현하고 싶었는데 설계하는 것이 어려웠다. 우선은 같은 서비스에서 호출하는 경우(요청 응답이 같은 경우)에 여러 서비스를 활용할 수 있게끔만 구현해보려고 한다.
    

# ⏳ 회고

### **Keep**

- **이동 시간 활용하기**
    
    이동시간을 활용해서 영속성 컨텍스트 관련한 영상을 보았다. 어제 학습이 필요하다고 생각한 내용들을 조금이나마 이해할 수 있었다. JPA를 잘 활용하면 데이터베이스에 현재 중복된 값을 갖는 필드들이 있는데 이를 없앨 수도 있지 않을까라는 생각을 해보았다.
    

### **Problem**

- **사용해보지 않은 기술을 사용하니 개발 시간이 오래 걸렸다**
    
    QueryDSL을 처음 사용해보았다. 아무래도 처음 쓰는 기술을 사용하다보니 간단하게 학습을 해도 활용하기 위한 기본 동작 흐름이나 문법이 익숙하지 않아서 구현하는데에 시간이 오래걸렸다.
    
- **구체적으로 계획을 세우지 않으니 어떻게 구현하지 라는 고민을 하는 시간이 많았다**
    
    외부 api를 호출하는 서비스를 만들어야 겠다라고만 생각을 하고 구현을 시작하려고 하였다. 설계를 하는 것도 아니고 구현을 하는 것도 아니어서 코드를 썼다 지웠다하는 무의미한 시간이 많았다.
    
- **설명을 못한다**

### **Try**

- **구현하다가 막히면 잠시라도 키보드에서 손을 떼고 생각하는 시간을 갖기**
    
    키보드 대신 펜을 잡고 어떻게 구현할지 고민하는 시간을 가져야 겠다. 하지만 빨리 기능을 구현하는 것도 중요하기 때문에, 너무 오랜시간(우선 30분) 동안 고민하지 않고 우선 구현하기로 해야겠다. 아니면 자투리 시간에 틈틈이 생각해보아도 좋을 것 같다.
