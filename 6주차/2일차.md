### 작업 과정에서의 배운 점

- 성급한 추상화
    
    원래는 API 호출하는 주체에 따른 응답 형식을 통일하려고 하였는데, 같은 주체여도 서비스에 따라서 형식이 다른 경우가 있었다.
    
    하나의 API 호출은 걍 하나의 클래스가 담당하도록, 만약 갈아끼우게 될 친구가 생기면 그에 대한 인터페이스를 만드는 것이 좋겠다. 길찾기 API 를 추상화 (자동차 길찾기, 다중 경유지 길찾기 둘 중 하나로 갈아끼울 수 있도록!)
    
- **테스트코드의 중요성**
    
    그 동안 서비스 코드를 작성하지 않았었는데, 유틸 클래스와 메서드를 분리하면서 해당 클래스에 대한 테스트 코드를 작성하였다. 이 과정에서 실제로 기존 코드에 오류가 있었다는 것을 발견하였고, 수정할 수 있었다.
    

### 어려웠던 점

- 외부 API의 응답 형식을 분석해서 필요한 데이터를 수집해오는 것이 오랜 시간이 걸렸다.
